| PAGE-WF-002 | 候选审批人；`/workflow/inbox` | L：待办过滤 → 任务 → 业务摘要/差异/意见 → 决定。业务引用来自owner，实例/任务ID、候选快照、版本、意见来自Workflow | 本人待办/已办/业务类型/时间；进入003；直链仍验证候选人，审批后回原过滤 |

## 2. 功能

| FUNC定义 | 页面/需求/原TC | 流程、契约与拒绝 |
|---|---|---|
| FUNC-WF-001 | 001；REQ-WF-001..005；WF-TC-001..004/009 | 1草稿校验图与白名单条件；2验证审批人非空、可达终点、无未支持循环；3发布新不可变版本；4多定义匹配按显式优先级，平级冲突拒绝而非随机。事务提交版本/审计；运行实例不随发布漂移 |
| FUNC-WF-002 | 002/003；REQ-WF-001..005；WF-TC-001/004..011/015 | 1owner提供业务引用/版本/安全快照；2唯一幂等创建实例/首任务/Outbox；3审批验证候选人、当前任务版本、意见；4按已发布会签/分支策略推进；5业务hook同步。决定已持久化而hook失败时保持待同步，不重复任务/决定 |
| FUNC-WF-003 | 003；REQ-WF-001..005；WF-TC-008..011 | 1核验撤回/驳回/取消当前状态；2终止/推进合法任务；3发业务事件/补偿；4对账业务版本。缺条件字段、类型错、业务变更、禁用审批人进入可诊断阻断，不默认通过、不删除审计 |
| FUNC-WF-004 | 004/003；REQ-WF-006..008；WF-TC-012..014 | 1按schema版本渲染；2前端/服务端校验字段白名单/类型/范围/权限；3保存实例数据和schema引用；4历史按原版回放。文件只允许Platform受权引用；未知字段/版本不可静默丢弃或当SQL列 |

审批命令包含taskId、expectedVersion、decision、comment、idempotencyKey；响应返回决定和业务同步状态。候选生成快照与当前账号有效性同时检查，候选重派规则未确认时不自动重算。会签必须使用任务原子版本和已发布策略；不同审批人的合法决定可各存一次，终态推进只能一次。Outbox/业务回调独立去重，终态不能重新审批。

## 4. 实现阻断

产品需确认首期分支/并行/会签种类、冲突优先级、撤回权限、禁用候选重派、业务hook一致性方案、超时/SLA与历史保留。未确认的策略不可作为可选项发布；设计器不能先提供引擎未验证的图元素。上手顺序为发布验证器→状态机/幂等集成→业务同步→页面→schema历史兼容。
