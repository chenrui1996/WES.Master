# T02 独立MySQL测试库方案

- 状态：实施中；用户已建库并授权后续开发测试使用，真实验证结果随实施记录更新
- 范围：T02真实MySQL门禁，依据[ADR-0002](../adr/ADR-0002-mysql-first-implementation.md)、[工程治理](../03-engineering-governance.md)
- 选择来源：先选择同实例独立库；2026-10-23用户确认已建`wes_test`并授权连接测试，随后明确要求后续MySQL使用Seven配置中的用户名/密码，不再就账号来源询问
- 不含：修改Seven配置、把凭据复制到WES文件/日志、访问现有业务库、全实例故障、生产控制

## 本轮授权调整

用户后续明确授权覆盖本文原先“不可读取Seven凭据、必须专用账号”的开发测试前置：读取已指定Seven配置的Database.ConnectionString，仅在内存保留同实例端点与凭据并强制目标库为`wes_test`。不把原连接直接交给数据库、不查询原库、不回显用户名/密码/连接字符串；不创建账号或更改全局权限。若账号具有管理员权限，本地目标校验是防误连而不是数据库权限隔离，风险继续登记，不能声称最小权限验收通过；生产部署仍须专用受限主体。下文专用账号分离方案保留为强化目标，不再阻断用户已批准的本机测试。

## 1. 方案与取舍

| 方案 | 隔离与代价 | 本轮决定 |
|---|---|---|
| 同实例独立库及独立账号 | 可验证真实引擎的迁移、唯一约束、并发和事务；共享服务进程及资源，不能证明实例级故障隔离 | 采用，专用库名`wes_test`；先做库级验证 |
| 独立实例 | 可测试断网、服务重启、实例恢复；需要额外实例和运维资源，当前容器不可用 | 后续准备，不以同实例结果代签 |
| 复用Seven业务库 | 可能破坏现有结构/数据，权限及清理边界不可靠 | 拒绝；不以改表前缀作为隔离替代 |

该库只保存可丢弃的合成测试数据，不复制业务记录、用户、密码、设备地址或实际运输任务。共享实例即使是本机也不是专属环境；测试负载有界、默认串行运行涉及DDL的测试，不能进行压力压满或实例级故障注入。

## 2. 身份与权限边界

下表为原先的最小权限目标，**不是当前账号的已验收权限**。用户已自行创建隔离库，助手不执行建库/建账号；本轮按后续授权沿用来源账号，已执行的探针迁移/合成数据操作见Provider记录。

| 主体 | 允许 | 不允许 |
|---|---|---|
| DBA初始化主体 | 单次创建经批准的`wes_test`及测试账号、核对实际授权 | 将管理员连接保存到仓库、提供给Host或常规测试 |
| `wes_test_migrator` | 仅`wes_test`的必要DDL和迁移数据操作；具体权限随已审核迁移确认 | 全局权限、授权转授、读写其他库、停止实例、任意建库 |
| `wes_test_app` | 仅`wes_test`中已装配owner表的必要SELECT/INSERT/UPDATE/DELETE；首片按实际最小集合授权 | DDL、跨库访问、全局管理、执行设备控制 |

生产强化目标是限定连接来源、不使用`'%'`通配host，并分离应用/迁移身份。本轮不更改用户授权来源账号或其权限，迁移仍不由Host启动自动执行。

**库名含下划线的授权注意事项：** MySQL的数据库级授权可能受通配符和`partial_revokes`语义影响；不能假定加反引号就把`wes_test`限定为字面量。生成授权SQL前确认准确引擎版本及相关配置，由DBA审核转义/授权方式，再核对有效授权只覆盖目标库。不得意外覆盖`wesXtest`等匹配名称，也不得通过探查业务表来验证拒绝效果。账号创建、口令、认证插件与精确授权语句均留待该步骤审核，不在未核版本时生成貌似可执行的通用脚本。

## 3. 配置与防误连

1. 按本轮明确授权，由测试装配读取指定Seven配置；生产Host不依赖Seven文件。不修改原文件，不使用原数据库；专用身份分离仍为生产强化目标。
2. 本片测试装配定位同级Seven配置，未来独立环境可由受保护配置替代并复用同一防误连校验。当前Host未读取该文件或测试连接；环境变量配置不是已实现能力。
3. 机密在本机受保护环境中注入，不在聊天发送，不写入仓库、普通日志、测试报告或命令参数；只报告引擎/Provider版本及脱敏环境标识。
4. 从授权来源构造连接时强制目标库为`wes_test`；每次打开连接前再次校验目标库、端点和凭据完整性，空目标/系统库/业务库直接拒绝，不回退到原库。账号沿用用户明确批准来源，不假称账号已限制权限。
5. 当前真实Provider测试尚未实现；将来显式选择该测试集合时，缺配置报告blocked/失败原因，不能静默跳过后声称全部通过。无数据库Host测试继续独立执行。

## 4. 测试、清理与不可执行动作

| 验证项 | 断言与隔离方式 |
|---|---|
| 版本/Provider门禁 | 核对实际server版本、EF与Provider的精确依赖范围；locked restore/build后才验证真实连接，不以NuGet版本号存在当兼容证据 |
| 初始化与迁移 | 审核迁移SQL及owner表清单；只对专用库执行，记录迁移前后状态及失败恢复，不执行生产自动迁移 |
| 权限 | 独立最小权限验收仍未执行；当前身份沿用用户授权来源，不以防误连校验冒充数据库权限隔离，不查询Seven数据 |
| 事务与约束 | 使用有界合成数据验证唯一冲突、提交/回滚、并发冲突；失败后断言持久化状态及副作用次数 |
| 库级失败 | 故意违反约束或在明确事务窗口注入应用故障，验证回滚/可重试边界；不杀服务或其他会话 |
| 测试清理 | 仅清理本次run ID对应的已知主键；迁移回滚仅涉及已审核的本测试owner对象，失败显式报告并保留诊断 |
| 误连反例 | 非批准库/账号/端点在连接前拒绝；缺配置不使用默认值，不把误连拒绝当MySQL业务测试通过 |

禁止DROP DATABASE、整库TRUNCATE、按模糊前缀批量删除对象、全局设置修改、停止MySQL80、故障重启或影响其他用户的连接/网络。需要这些实验时升级为独立实例方案并重新授权。连通性通过也不解除现场H门禁。

## 5. 审核后执行顺序及放行证据

1. 用户已确认建库，连接端点取自明确授权来源，不猜测其他端点；实测server为8.0.12，目标为`wes_test`。
2. 本轮锁定测试评估Provider并验证真实迁移/事务；不再重复建库/建账号。以后推进最小权限强化时单独审核授权SQL。
3. 用户已授权沿用指定来源用户名/密码，不再询问账号；助手不修改来源、不持久化/输出凭据，不扩展为现有业务库授权。
4. Provider测试按失败→修复→复测闭环，精确版本、命令、断言及清理结果见[Provider记录](03-mysql-provider-foundation.md)。
5. 仅在T02适用门禁全部通过后评估T03；T01具名角色、SQL Server/PostgreSQL延后兼容、实例级故障及现场H分别保留状态。
