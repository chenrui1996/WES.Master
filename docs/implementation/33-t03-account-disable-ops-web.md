# T03/T04运维用户页凭据禁用闭环

- 状态：已实现并通过切片验证；T03/T04仍未整体完成。
- 范围：将现有授权凭据禁用HTTP动作接入Ops Web用户目录；用户档案停用与凭据停用仍是不同的owner命令。
- 依据：[禁用owner及HTTP合同](16-audited-account-disable.md)、[T04目录字段投影](18-t04-directory.md)。

## 实现

- `UserDirectoryRow`增加非秘密`CredentialVersion`，仅当该目标用户当前拥有`platform.users.read`的`Credential`字段时才查询并投影；数据库查询只选择`UserId`和版本，不读取/序列化凭据hash或原始秘密。
- 用户页仅对`Enabled=true`、有受权凭据版本并满足当前本地`Enabled`写字段授权检查的行显示“停用登录凭据”。这只是UX预筛；实际权限、租户、账号状态和版本由后端禁用owner重新核验。
- 点击动作先打开具名确认表单，明确说明其撤销全部会话、不改档案/角色且不能从页面重新启用。提交只携带用户ID与当前凭据版本，成功后重新读取列表；仅该HTTP 204命令显式允许无内容成功，其他写入仍要求既有decision响应；冲突/撤权使用既有明确错误与重读路径。
- 既有档案编辑开关继续使用目录用户版本；不将两个版本合同互换。客户端不为此非回执owner命令自动发送误导性的`Idempotency-Key`。

## 边界

页面未增加启用/重置密码功能，不缓存凭据版本到浏览器持久存储；缺`Credential`读取授权时无版本、无凭据操作入口。隔离HTTPS真实浏览器流程覆盖显式确认、204、目录重读后停用入口消失及数据库凭据停用状态；生产授权部署、PDA和现场H仍独立待验。T03/T04整体保持partial。
