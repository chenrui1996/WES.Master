# T06 用户角色关联独立回填

- 状态：首片已验证；范围限定为 Platform Users 当前角色关联的受权摘要解析与编辑回填，不代表 DTC-UI-022 或 T06 完成。
- 依据：[密集页面交互合同](../detailed-design/03-dense-page-interaction-contract.md) §3、§4.1、§4.2.4、DTC-UI-021/022/024；[Platform 页面与功能设计](../detailed-design/platform-and-security.md) PAGE-PLAT-003、DTC-PLAT-014。
- 测试记录：[用户角色关联回填测试](82-t06-user-role-reference-resolution-tests.md)。

## 目标与实施思路

Platform Users 已有角色多选只读取分页候选。用户保存的角色可能不在当前25条候选页，原界面会把未解析的角色 ID 显示为标签，且无法独立确认受权代码、启用状态或保留关联。新增由 Platform Directory owner 提供的有界批量引用解析：编辑器按已保存角色 ID 查询，而不是扩展候选页或预取租户全部角色。

角色是 tenant-wide owner 资源。解析必须由当前主体对 `platform.roles.read` 的 `Id` 授权启用；其它字段仍按同一 owner 当前可见字段投影。输入每批1至100个非空 ID，重复 ID 去重；不存在或不可见的角色不出现在结果中。不能从缺失项推断角色存在性，也不能回传未授权代码。HTTP 使用重复 `ids` 查询参数并拒绝空批次、空 GUID 和超过100项的原始输入。

Users 页面只在明确打开已有用户角色编辑时解析引用；请求按100个分批，身份/目标切换或关闭编辑时取消并以代次隔离迟到结果。角色代码可见时用代码显示，启用值为false时标注停用；代码/状态缺字段、无权或不存在统一使用受限摘要，不能把内部 ID 当名称。引用解析失败显示局部错误，不改变已加载用户版本或已保存角色集合。独立回填只提供当前保存关联的展示事实，不会将其扩充为新增候选。已保存、当前启用且代码可见的关联可以作为原有关联保留；停用、缺失或无权解析的关联不能作为候选或保留，移除必须由管理员显式操作。现有写操作仍在服务端复验完整的委派权限、租户和版本，不以回填结果代替授权。

列表角色摘要仅使用当前已加载且授权的角色候选投影；缺少摘要时显示通用受限文案，不显示原始关联 ID。切片不改变用户权限字段、角色可委派规则或后端成员写入语义。

## 不在范围内

不实现名称模糊搜索、跨模块角色解析、Users 页候选缓存、批量角色写入或角色编辑策略变化；不声称隔离HTTPS Chromium、DTC-PLAT-014整体或T06整体验收完成。
