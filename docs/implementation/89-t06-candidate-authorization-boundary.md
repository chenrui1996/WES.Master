# T06 候选授权与取消边界

- 状态：已验收（Users/Roles及共享候选的本地组件切片），T06整体仍未完成。
- 范围：续实施计划第2节；DTC-UI-021/022/024关联候选交互，遵循密集页面交互合同第3、4节。不改变授权权威、API、引用详情解析、后端或依赖。
- 现状：候选新查询保留旧行；拒绝/HTTP失败不清行；取消只中断transport，忽略abort的迟到响应仍可能生效；旧失败仍会抛给页面。
- 设计：每次请求有独立generation；新查询立即清候选与more；reset/外部取消立即清状态并使请求失效。只有当前且未取消请求能提交行、more、loading或抛出错误。过期成功/失败返回null，页面不得将null当作拒绝。
- 已取消signal的迟到调用只返回null且不发请求，不能reset另一个正在进行或已完成的新查询；取消权只作用于绑定该signal的请求。
- 当前401/403、authorized非true及非法候选页清行与more，并通过响应式denied状态通知消费页清除编辑目标、草稿和名称摘要。普通失败也清候选（不保留可选择的无效快照），仍抛出供页面显式提示；重新读取成功可恢复。
- Users关闭用户/部门编辑、清角色就绪状态；Roles关闭角色编辑并清未提交规则及摘要。正常代码筛选仍保留已选摘要；授权拒绝则清除，不改变正常历史引用resolve契约。
- 当前追加请求或代码查询的普通失败也关闭相关编辑，防止已选摘要继续成为无效状态下的可提交来源。被取消的null结果不被消费页解释为无权；消费页不再重复写入组合式逻辑持有的候选行。
- 401沿用现有identity API的全局登出安全处理，页面显示“无权读取…请登录”，不增加前端独立授权判断。
- 保持每页25、精确code筛选与offset推进、稳定ID去重；候选不是最终授权或资源预留。
- 验证：受控Promise覆盖append/new read丢权、重置/取消/新筛选的晚到成功与失败，真实Users/Roles组件覆盖草稿、受保护标签、显式错误及恢复。不宣称浏览器E2E、完整DTC或生产验证通过。
