# Platform 与安全详细设计

## 1. 设计目标与边界

Platform 提供身份、授权、组织/数据范围、租户、安全控制、配置、文件、审计和跨域基础服务。它定义安全规则并向业务模块提供应用契约，不拥有 WMS/WCS 单据、库存或设备行为。

所有 API 必须在服务端完成认证、授权、数据过滤和输入校验。前端动态菜单、按钮隐藏、PDA 本地缓存和路由守卫仅改善体验，不能代替授权。安全配置关闭或依赖未配置时，必须按显式策略启动失败或拒绝受保护操作，不允许静默放宽权限。

## 2. 身份与会话

### 2.1 登录与令牌生命周期

1. 登录验证账号状态、密码哈希、验证码（若当前环境启用）和限流；错误响应不泄漏账号是否存在。
2. 成功后签发短期 Access Token 和可撤销的 Refresh Token。Refresh Token 必须在服务端可识别、可撤销，存储只保留不可逆摘要或受保护值。
3. 每次刷新均原子地消费旧 Refresh Token 并签发新令牌；并发刷新仅一个成功。检测到已消费令牌再次使用时按会话重放事件处理并撤销关联会话，规则和用户提示需明确。
4. 登出撤销该会话；改密、禁用账号、重置凭据或安全管理员撤销操作按策略撤销全部会话。
5. Token Claims 仅包含身份、角色/权限解析所需的最小值和租户上下文；高权限变更需在有效期内生效，不能无限期依赖旧 Claims。

凭据参数（Access/Refresh 有效期、尝试次数、锁定期限、密码历史和复杂度）由部署策略确定并纳入安全 ADR；不得把示例值误当生产默认值。

### 2.2 验证码、限流与防重

- 验证码使用随机不可预测 key、短时有效、一次消费；响应不得把明文答案返回生产客户端或日志。开发测试可用受控测试注入，不共享生产路径。
- 登录限流结合 IP 和账号风险维度，避免仅按客户端可伪造的身份字段限流。返回安全的重试提示且不暴露内部阈值。
- 全局/API 限流按资源成本分层；Route/控制类命令、登录和普通查询采用不同策略。明确代理可信链，否则客户端 IP 不可信。
- `Idempotency-Key` 对写操作按租户、主体、操作和键作用域绑定请求摘要。相同键/相同请求返回首次确定结果；处理中请求返回可重试的冲突状态；相同键/不同请求拒绝。保留期限覆盖客户端重试窗口。
- 重复提交机制不能替代领域唯一约束、并发控制或消息消费者幂等。

## 3. 授权、数据范围与租户

### 3.1 授权判定

权限由服务端 Policy/应用权限检查执行，遵循 deny-by-default。权限标识稳定、可审计；系统角色的特权例外集中定义、限于具体操作并测试，不以硬编码用户 ID 放行。

检查顺序：认证主体有效 → 模块/操作权限 → 租户边界 → 数据范围/资源归属 → 状态机允许当前动作。所有拒绝操作按敏感级别写审计；不记录令牌、密码或完整敏感请求体。

### 3.2 数据范围

- 每个查询明确采用全部、本部门、本部门及下级、本人或业务专属范围中的哪种规则；范围过滤在服务端查询中、分页和聚合之前执行。
- 写操作按资源当前所有者/组织重新验证，不能仅信任请求 DTO 中的 `CreateId`、部门或范围值。
- 空白范围集按显式 deny/no rows 处理；不得将“空集合”同时解释为“全部数据”。
- 对不适用数据范围的系统任务使用明确的系统主体和审计原因，而不是关闭过滤器逃逸。

### 3.3 多租户

- 租户 ID 从已验证身份或受信任服务主体获得，不采信客户端任意租户值。
- 每个租户拥有的数据行带租户归属；复合唯一约束包含租户键。公共配置必须是有限、只读或平台拥有的共享数据类型。
- 所有查询、更新、后台任务、消息消费者和缓存键都必须包含租户边界；管理员跨租户操作单独授权并审计。
- WES 不自动继承 Seven `TenantId=0` 的可见性规则；公共数据类型和访问策略需由 ADR 明确。
- 租户上下文缺失/非法时对租户资源 fail closed；测试覆盖后台作业无交叉读取/写入。

## 4. 配置、字典、国际化与文件

- 配置按环境外部化；机密仅经 Secret Store/环境注入，严禁进入仓库、数据库普通配置、审计或客户端包。
- 配置读取有强类型验证和启动检查。可选能力使用显式 Disabled 状态；若调用不可用服务返回明确错误，而非伪造成功结果。
- 字典和国际化资源由授权维护；业务代码不依赖展示文本判定状态，存储稳定代码、按客户端本地化显示。
- 文件上传需限制扩展名/MIME/大小、校验文件内容、生成不可猜测对象名、做授权下载和恶意文件扫描策略。原始文件名只作为受控元数据；对象存储失败不得留下“已上传”成功状态。
- 文件关联业务实体时，先执行业务授权和租户隔离；删除采用引用检查/软删除或明确清理任务。

## 5. 审计、异常、日志与健康

- 审计事件记录主体、租户、动作、目标资源、结果、时间、关联 ID、必要的变更前后摘要和来源；敏感字段按字段级规则脱敏。
- 审计不可被普通业务身份修改/删除；数据保留期、访问权限和导出审计需部署方确认。
- 业务错误使用稳定错误码、可本地化的安全消息和相关字段信息；内部异常只进入受控日志，不回传堆栈/连接字符串/设备秘密。
- 所有入口、消息消费和后台作业携带 CorrelationId；跨系统调用同时保留 CausationId 与业务单据/任务 ID。
- Health 分离 liveness（进程能工作）与 readiness（必需依赖可用）；非必需依赖降级要显示明确状态和影响范围。
- 指标使用低基数标签。禁止把用户 ID、单号、设备序列号等高基数/敏感值作为 Prometheus label。

## 6. 权限与失败场景

| 场景 | 预期 |
|---|---|
| Access Token 无效/过期，Refresh Token 已撤销 | 拒绝请求；不执行写入；审计必要的安全事件 |
| 一个 Refresh Token 并发刷新 | 一个原子成功；另一个确定失败并触发重放/并发规则 |
| 请求缺权限但前端可见按钮 | 服务端拒绝；数据库无副作用 |
| 租户/数据范围上下文缺失或资源跨租户 | fail closed；不泄露目标是否存在 |
| 同幂等键相同请求重试 | 返回同一逻辑结果；仅有一次业务副作用 |
| 同幂等键不同请求体 | 拒绝冲突，不覆盖第一次结果 |
| 日志序列化包含凭据或大文件内容 | 脱敏/拒绝记录敏感字段，不影响受控错误处理 |
| 配置缺失、文件存储/鉴权依赖不可用 | 必需依赖 readiness 失败或操作返回明确依赖错误；不返回成功形状 |

## 7. 验收用例

| ID | 覆盖场景 | 断言 |
|---|---|---|
| PLAT-TC-001 | 有效/无效账号登录及账号枚举 | 成功只发生于有效凭据；失败响应外观不泄露账号存在性 |
| PLAT-TC-002 | 验证码过期、错误、重复使用、关闭开关组合 | 错误和重放拒绝；启用条件符合配置；生产不回传答案 |
| PLAT-TC-003 | Refresh 轮换、并发刷新、旧 Token 重放、登出 | 原子轮换、旧 Token 不再有效、撤销范围符合规则 |
| PLAT-TC-004 | 改密、禁用用户、管理员撤销会话 | 相关会话在规定时限内不能继续写操作 |
| PLAT-TC-005 | 未认证、无权限、隐藏菜单后直接调用 API | 所有未授权写请求被拒绝且无副作用 |
| PLAT-TC-006 | 本人/部门/下级/全部范围的查询与更新 | 分页、计数、导出和写操作使用相同范围 |
| PLAT-TC-007 | 租户 A 查询/修改租户 B；缺失租户上下文的任务 | 无跨租户读写；返回一致的拒绝语义 |
| PLAT-TC-008 | 空范围集合、未知数据范围值、伪造资源所有者 | 按 deny-by-default 处理，不因空集合回退全部 |
| PLAT-TC-009 | 限流与可信反向代理头伪造 | 阈值按配置应用；非可信转发头不能规避限制 |
| PLAT-TC-010 | 幂等请求成功重放、处理中重放、键复用不同正文、过期键 | 结果与副作用符合幂等状态机 |
| PLAT-TC-011 | 恶意文件名、伪装 MIME、超限、无权下载和存储故障 | 文件不公开、不越权；失败无孤儿的成功记录 |
| PLAT-TC-012 | 审计脱敏、拒绝写审计、日志查询越权 | 敏感信息不泄露；审计可追踪且普通用户不可篡改 |
| PLAT-TC-013 | 必需/可选依赖离线及错误码序列化 | readiness/操作结果准确；无成功形状 fallback 或堆栈泄漏 |
| PLAT-TC-014 | Provider 下唯一键、租户复合约束、并发写入 | SQL Server/PostgreSQL/MySQL 的约束与错误语义均验证 |
| PLAT-TC-015 | 配置缺失、格式错误、热更新期间读取 | 启动校验指出配置键；请求只见完整旧版或新版配置，不见半更新状态 |
| PLAT-TC-016 | 字典项停用/删除但仍被业务行引用 | 稳定代码不被物理删除造成历史误读；写入新值受授权/状态校验 |
| PLAT-TC-017 | 国际化资源缺失、默认语言回退、用户切换语言 | 业务状态/错误码不依赖翻译文本；客户端回退规则一致 |
| PLAT-TC-018 | 本地/对象存储切换、对象上传中断、孤儿文件清理 | 配置切换不泄漏对象；失败可重试/补偿，清理任务不删仍被引用文件 |
| PLAT-TC-019 | HTTP → application → message/job 跨边界关联 ID 和敏感字段日志 | trace/correlation 可串联；日志不含令牌、密码、完整 payload 或高基数 metric 标签 |
| PLAT-TC-020 | Liveness/readiness、必需/可选依赖变化、指标导出 | liveness/readiness 语义分离；依赖状态正确；指标标签低基数且不暴露隐私 |

## 8. 未决参数

Access/Refresh 生命周期、锁定策略、数据保留期、租户启用方式、公开配置定义、文件扫描服务、审计保留期限、限流预算及生产依赖等级均需安全/运营负责人在部署前确认；设计可以先定义接口与验收结构，不虚构现场数值。
