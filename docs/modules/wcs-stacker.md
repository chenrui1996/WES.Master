# Stacker WCS 详细设计

- 状态：目标设计；保留 Seven 已有包业务，Route 算法由 Route 专项重构
- 范围追踪：`SCOPE-WCS-01`、`SCOPE-PDA-02`
- 基线参考：[WMS/WCS 实现说明](../../../Seven.Master/doc/20-WMS与WCS实现说明.md)、[Route 现状分析](../route/01-as-is-and-research-review.md)、[Route 目标设计](../route/02-target-routing-and-scheduling.md)
- 测试前缀：`STK-TC-*`

## 1. 包边界和核心状态

Stacker 包拥有巷道/位分配策略、设备/段任务、双深组和挡路任务、申请点、该包路网/交通运行状态与设备反馈。它只管理执行动作，不维护可扣减库存。WMS 提供货位与库存权威数据；Orchestration 下发/接收 Leg；Device Adapter 处理设备协议。

常见业务对象：PutAway Task、Retrieval Task、Device/Segment Task、Request Point、Aisle Assignment、Location Profile/LockBin、Route/RouteFlow。WES 设计将这些能力映射为模块内聚合/表，旧表名不构成兼容要求。

## 2. 入库分配与目的地点申请

1. 校验 Leg PackId、起终点、货位主数据、仓库启用状态及请求点类型。
2. 选巷策略过滤禁用巷道、盘点锁、最低空位阈值和策略适用范围；再用权重、轮转与确定性 tie-break。
3. 选位仅从同巷、Stacker 包、可用且符合双深规则的候选中挑选；原子预约目标位/双深组并绑定申请/任务 ID。
4. SUDR（目标地点请求）结果有 `Accepted/Rejected/Waiting/Invalid` 等明确语义；不属于 Stacker 的请求点由其他 Pack 处理，不由本包误报拒绝。
5. 若选定目的点或目标位变化，记录策略/地图版本、原目标、新目标和原因；释放旧预约与创建新预约须原子或有恢复流程。

## 3. 双深和挡路移库

- 双深组的占用深度必须满足物理深度规则；禁止孤立占用不可达深位、对已占用目标位再次预约或在未知容器状态下推定空位。
- Retrieval 访问深位前执行挡路检查。浅位阻挡时，创建有独立业务引用的 StackerTransfer，先把浅位移到同巷安全空位，再恢复原取货任务。
- 同组任务按明确优先级/公平规则推进；提高优先级不能无限饿死其他组。
- 移位计划失败时保留原库存/位置事实，解除或延长预约按失败类型处理；不得仅通过改变 WcsPri 伪造已安全排序。
- 硬锁位、设备不可达和盘点锁是不同阻断原因，错误/运维视图需区分。

## 4. Route 拆段与设备执行

Seven 的现状以 `StackerRouter` 加权 Dijkstra 选择边，满容量边不可用，并计入占用成本；`StackerPathDispatcher` 根据执行堆段拆成多段任务、仅首段派发、段完成后释放流量再派发下一段。目标预约权威遵循 [ADR-0001](../adr/ADR-0001-route-reservation-authority.md)，算法与安全/活性策略详见 Route 专项。

执行状态必须绑定 WCS Task、Leg、Segment、Device 和 map version；反馈含命令/段 ID、顺序/时间与结果。仅接受当前活动段的有效反馈；重复反馈幂等；取消/失败释放尚未进入物理占用的预约，已占用资源须在权威反馈确认车辆离开后才释放，未知位置保留保护并留下可恢复记录。设备无可用真实 Adapter 时可使用仿真语义端口；生产不得因 `InMemory` 回执标为真实物理完成。

## 5. 失败和人工恢复

- 点位/地图缺失、路线不可达、容量满、双深不合法：任务拒绝或等待，不派发物理命令。
- 反馈超时：标识设备状态未知，先查询/人工确认，不假设任务未执行。
- BlockingPoint 改道：验证新路线与预约，旧段取消确认后再释放旧资源。
- 强制完成/取消/重新发送可从统一 2D 运维地图进入，但只由 Stacker Pack 在高权限审核/审计和最终安全校验通过后执行；不得从普通 PDA 绕过。
- Pack 必须在命令执行前重新校验任务版本、设备能力、活动 Route/资源占用和联锁；跨包协调与操作者工作流见 [Orchestration 运维协调](orchestration.md#8-wcs-运维协调边界)，本包保留最终执行/拒绝权。
- 故障恢复后根据设备当前位置和货物事实重建状态；不得只清理 DB 队列让 Route 看起来畅通。

## 6. 详细验收用例

| ID | 场景 | 期望 |
|---|---|---|
| STK-TC-001 | 入库巷道策略候选为空/全部禁用/权重轮转 | 明确不可分配；无部分预约 |
| STK-TC-002 | 盘点锁巷、最低空位边界、仓库 Pack 不启用 | 该巷被排除且记录原因 |
| STK-TC-003 | 同等权重候选/轮转并发 | tie-break 稳定、轮转状态无重复分配 |
| STK-TC-004 | 双深空位/浅位占用/深位孤占/组内锁位 | 只允许物理规则合法的目标；错误配置 fail closed |
| STK-TC-005 | 两个任务竞争同一位/同一深位组 | 只有一个原子预约成功，资源归属可查询 |
| STK-TC-006 | 深位检索无阻挡/被浅位阻挡 | 正常取货；阻挡场景先建立独立移库，再恢复原任务 |
| STK-TC-007 | 移库失败/取消/目标被并发占用 | 原库存事实保持；预约释放/恢复路径明确 |
| STK-TC-008 | Stacker/Other Pack 请求点混合订阅 | 本包仅接收自有支持类型，不误拒其他包请求 |
| STK-TC-009 | 无路网兼容模式、容量满、无路径 | 按已配置策略处理；不声称不存在 Route 仍安全可行 |
| STK-TC-010 | 多段 ExeStack 路径首段派发和反馈推进 | 仅当前段执行；段完成后依次推进且资源不泄漏 |
| STK-TC-011 | 重复/乱序/错误设备段反馈 | 非当前段不推进；重复事件无重复完成 |
| STK-TC-012 | Route/map 版本在任务执行期间更新 | 活动任务保留绑定版本或经安全重规划，不混用新旧边 |
| STK-TC-013 | 反馈超时、断连、状态未知后重启 | 进入安全暂停/核查；占用可恢复且可见 |
| STK-TC-014 | 从 2D 运维地图强制完成/取消未授权、授权但无理由 | 请求拒绝；高权限覆盖完整审计，地图只在有效 Pack 回读后更新终态 |
| STK-TC-015 | StackerTransfer 完成后原 Retrieval 恢复 | 库存只在 WMS 回调变更一次；原取货任务顺序恢复 |

## 7. 未决运行参数

双深硬件容量/行驶规则、设备段切分语义、请求点有效期、超时阈值、最大并行段数、Route 目标成本、无地图行为是否允许、生产 adapter 控制范围需现场/设备方确认；Route 阈值统一由 Route 专项定义。
