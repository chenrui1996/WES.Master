## 1. 领域职责与不变量

WMS 是物料数量的唯一权威。所有收货、预留、释放、发运、移库和盘点调整都通过 WMS 用例写账；WCS、PDA、外部 ERP/MES、SCADA 和 Simulator 不直接修改余额。

### 1.1 核心不变量

1. 对每个租户/仓库/货位/物料/批次/容器维度，账本流水可以解释余额变化；库存修正采用补偿流水，不静默修改历史。
2. 数量单位明确；`Qty >= 0`、`AvailableQty >= 0`、`AvailableQty <= Qty`。Qty是WMS账面量，预留减少可用量但不提前改账面量；在途与预留可重合，按受保护数量并集扣可用量、同一执行单元不重复扣减，不新增独立冻结业务。
3. 同一库存资源并发预留不能超过可用量；以数据库并发控制/唯一约束保证，不依赖客户端读后写。
4. 位置占用、预约、容器归属和库存余额必须通过同一 WMS 事务/应用用例保持一致；路网临时预约不等同库存占位。
5. 运输完成以有效的运输/leg 相关 ID、预期来源/目标、容器和状态验证；完成回调可重复但只能造成一次账本效果。
6. WCS 包状态不是库存事实；运输失败、取消或设备超时不能直接视为收货/发运成功。
7. 多租户/数据范围作为键与授权条件进入所有读取、写入和唯一性约束。

## 2. 主数据与分配边界

仓库、库区、层、巷道、货位、容器以及 WCS Pack 绑定由 WMS 拥有。货位包含明确的仓库、PackId、位置编码和运营状态；编码校验由包 schema 合同完成，WMS 不在核心服务里硬编码供应商地址格式。

货位区分至少以下业务状态，具体是否物化为字段或由占用/预约记录投影由实现 ADR 决定：

- 可用空位：可被合法收货/移库分配。
- 已预约：由唯一有效业务/运输操作持有；过期释放需核验持有人状态。
- 已占用：有容器/库存，不得被另一任务分配。
- 锁定/不可用：盘点、维护、异常等原因及责任人/期限可查。

WMS 验证仓库启用对应 Pack、货位编码/Pack 一致、目标位置可用和权限；具体 Stacker 双深、FourWay 层巷位等几何和交通策略由相应 WCS 包负责。

## 3. 收货、入库与上架

### 3.1 业务步骤

1. 创建入库单草稿：业务单号/来源类型唯一，行包含物料、计划数、单位和可选批次/收货约束。
2. 审核：只允许 Draft；校验行数据、仓库、权限和业务扩展 hook。重复审核按幂等语义返回已有结果或确定拒绝。
3. 收货登记：操作员扫码确认实际数量/容器/收货位。服务端校验订单剩余量、容器、货位、物料和幂等键；写收货流水并更新实际收货。
4. 分配/组盘：确定目标位置。如果目标异于收货位，创建唯一运输意图并把单据/明细与 transport reference 关联；不直接创建包内任务。
5. 执行回写：Orchestration/WCS 反馈完成后 WMS 验证来源/目标/数量/容器，并在一个 WMS 事务内移动库存、释放源预约、占用目标并更新明细/单据。

状态建议：入库单 `Draft → Approved → Executing → Completed`，失败/取消需单独记录原因和补偿状态；明细 `Created → Received/Transporting → Completed`。同址收货可以没有运输 leg，但仍需明确其收货位和终态。

### 3.2 收货与运输失败

- 收货入账成功但目标分配/运输创建失败时，保留在收货位并标为待处置，不能回滚真实已收货事实。
- 确认尚未移动的运输拒绝/终止，保留源位事实；已在途/已交接不能假定实物仍在源。账面归属、执行保管权和观测位置分开；相关量不可再次分配，Unknown先对账，不凭失败状态释放保护。
- 重复的收货确认、运输完成、取消回调通过业务幂等 ID 去重。
- 入库超收、错物料、容器/位置冲突等结果显示可操作错误，不将请求记为成功。

## 4. 出库、预留、拣选和发运

### 4.1 预留规则

出库草稿包含订单、行、数量、分配来源位/容器、必要目标位、组号/优先级。审核时验证库存可用量并原子预留；预留数量同时记录来源订单行和生命周期状态。取消/修改订单必须先验证是否已有执行/运输动作，再释放未消费预留。

### 4.2 处理分支

| 分支 | 处理方式 | 账本时点 |
|---|---|---|
| 无 WCS 运输的平库直发 | WMS 校验预留与权限，完成发运 | 发运事务内消耗实物量和预留 |
| 需由 WCS 取货/移至交接位 | Orchestration 创建 Transport Order/Leg；WCS 完成后 WMS 应用回调 | 审核只预留；完成时移动或扣减 |
| 拣选任务 | 生成与订单行/预留关联的拣选任务；PDA/Web 在线确认 | 拣选确认本身是否仅确认拣选、是否触发运输，由任务类型决定，不能跨分支混用 |

Seven 基线支持出库审核/库存预留/拣选确认/运输回写与无运输发运；`SCOPE-WMS-04` 中的测试证据可见 [PickingServiceTests](../../../Seven.Master/Seven.Net8/Seven.Tests/Wms/PickingServiceTests.cs) 和 [WMS 服务测试](../../../Seven.Master/Seven.Net8/Seven.Tests/Wms/WmsOrderServiceTests.cs)。WES 规格必须把 `Booked/Reserved` 与实际 `Shipped/Completed` 分开，避免仅确认拣选即误扣实际库存。

### 4.3 取消、短拣和异常

- 审核前取消只关闭草稿。
- 已预留未执行时，取消可释放预留；已生成运输或物理执行后，必须通过 Orchestration/WCS 安全取消或人工恢复，再由 WMS 完成补偿。
- 短拣/差异数量记录原因、实拣数和未完成数；不得静默改写计划数量或强行完成整单。
- 手工发运与已挂运输互斥；当前 transport state 必须由服务端重新检查。

默认超收/超发容差0，允许部分收发但剩余不自动关闭；部分实物完成后受权关闭剩余使用ClosedPartial，不伪造全单Completed/Cancelled。短拣不调账/不自动释放预留；Qty10/Reserved7、实拣5缺2仍10/7，确认未执行短缺释放2后10/5，合法发5后5/0。计划7和未完成2保留，余量默认开放。

## 5. 移库与跨包交接

WMS 移库是有来源/目标/数量/容器/原因的业务意图。内部移库由 Orchestration 路由并管理包间 Leg；WMS 只在确认到达后移动账本。跨包必须在配置的 handover point 完成交接，两个包的内部任务不得共享/改写对方 Route 预约。

首期中间交接不另做库存流水；在途数量仍有WMS来源账面归属，但标inTransit且不可再分配。bookLocation、executionCustodian、observedLocation/时间/质量分栏。唯一handover token由Orchestration协调双方证据，目的ReadyToReceive不等于下一Leg已激活；源交接完成且目的接受后才推进唯一保管权/下一Leg。任一结果未知保持资源和容器保护，不新造库存owner。

若移库为人工搬运，记录操作员、扫码源/目标、数量、时间、幂等键和审计。若出现来源库存已变、目标被锁、容器不符或反馈冲突，进入可查询异常态，不自动二次扣减。

## 6. 盘点

1. 创建计划时记录范围和参考快照；默认位/容器局部锁、盲盘。计数开始前重新获取一致库存快照/版本并验证无在途，相关任务存在则等待/阻断，不强撤命令抢锁。
2. PDA/运维端录入实盘数量，记录扫码位置、物料、容器、操作者、时间和版本；重复扫码/更正以修订记录呈现。
3. 全部应盘行已计数且所有非零差异经非盘点人授权复核后，WMS通过调整流水写差异；不自动调账，不直接覆盖余额。
4. 有效锁期间拒绝影响范围的新运输/收发；30分钟仅提醒负责人，不自动解锁。受权人工解锁立即使计数失效，必须重盘，旧版本不得调整。

Seven 基线的 `CreatePlanAsync` 以当前库存形成账面数量、`RecordCountAsync` 写实盘和差异、`ConfirmAdjustAsync` 应用差异；WES 需补足在途任务/并发库存变化及差异授权测试。

## 7. 扩展单据和业务挂钩

### 7.1 TransferOrder（Seven 已有扩展样例）

Seven 有仓内 TransferOrder 样例：Draft → Approved（预留来源库存）→ Completed（确认来源扣减并目标收货），使用独立业务单/行与 `IStockService`，服务和基础测试均存在。WES 保留其业务意图和扩展归属，但不照搬当前服务实现细节。

目标流程应当：

1. Draft 校验单号唯一、行数/物料/数量、源/目标存在且不相同、容器/Pack/租户正确。
2. Approve 在一个可恢复一致性边界内校验所有行并预留全部数量；有任一行失败就不允许只留下部分 Approved/Book 状态。
3. 需要设备运输时，由 Orchestration 创建关联运输意图；无需运输时走人工确认路径。两者状态不能相互伪装。
4. 每个实物已确认执行单元通过预留/运输引用/数量版本核验，在WMS本地事务提交源消耗、目标收入、预留消费、行进度和Outbox。A行已提交不因B失败回滚；B实物已到但记账失败保留来源量/目标冲突保护及同步异常，恢复只补B，不再运A。
5. 重复 Approve/Complete、并发确认、取消和库存变化均有幂等/并发规则；补偿通过反向流水和新状态完成，不删除历史。

父单Draft→Approved→Executing→Completed；部分完成仍Executing，独立executionStatus/ postingStatus按[规则§2.2](../detailed-design/05-approved-rules-and-defaults.md)展示，全部计划完成且记账同步才Completed。未执行全取消才Cancelled；有部分事实后关闭未执行余量用ClosedPartial。只有纯人工一次确认且全部同DB事务、尚无独立实物完成事实的路径可整单DB原子；分次搬运使用逐单元路径，反向实物补偿另建授权运输。

测试需从原有“基础调拨成功”延伸到多行原子性、库存不足、运输闭环、取消/重试和 provider 事务行为。冻结/解冻、拆托/合托、报废、补货等是 Seven 扩展规范列出的潜在业务样例，除非代码/测试核实，不宣称已在 Seven 实现；作为独立需求由业务确认。

### 7.2 扩展单据通则

项目单据通过稳定 WMS 应用契约调用标准库存、拣选、运输接口；单据自己的状态、表和权限归所属业务模块。允许经过审核的校验/生命周期 hook，但 hook 必须可观测、可测试、可幂等；禁止在标准 WMS 内核追加项目专属 `if`、重复维护余额或直接调用具体设备。

## 9. 已定规则与投用门禁

RULE-01..08已按规则基线确定：跟踪按物料显式策略/迁移不丢、数量decimal string/精度、部分允许且超收0、预留只提醒、局部锁盲盘、最终到达记账/逐单元执行、换算默认关闭、不允许负库存、账本不自动删。尚需迁移物料/单位/跟踪映射、真实Provider并发/精度、设备交接与最终完成证据；H缺项阻断对应控制，不能将已定B/P继续作为任选未决。
