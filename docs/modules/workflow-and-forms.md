# Workflow 与动态表单详细设计

- 状态：目标设计；保留 Seven 运行时流程/表单能力，不依赖源码生成器
- 范围追踪：`SCOPE-WF-01`、`SCOPE-WF-02`
- 基线参考：[Seven 工作流](../../../Seven.Master/doc/05-工作流.md)、[业务扩展规范](../../../Seven.Master/doc/23-业务扩展规范.md)
- 测试前缀：`WF-TC-*`

## 1. 目标与范围

WorkflowForm 拥有流程定义、已发布版本、实例、审批任务、审计历史和运行时表单 schema。业务模块拥有自己的单据状态；流程只能通过业务模块提供的 hook/command 完成审批关联状态变更，不能凭动态 `WorkTable` 字符串直接更新任意表。

Seven 文档既描述线性 `StepOrder` 推进，也记载条件 Filters 和会签行为。WES 不把设计器展示能力推断为全部运行语义已验证；条件、会签和分支规则须以发布版本和可重复测试为准。

## 2. 流程定义和发布

- 流程草稿包含业务类型、版本号、适用条件、步骤、审批人策略、步骤进入条件、超时策略及表单 schema 版本引用。
- 发布时校验定义图：起点/终点唯一、所有可达路径有合法终止、审批人非空或有明确 fallback、条件字段在允许字段集、无循环（除非显式支持有界循环）。
- 发布版本不可原位修改；编辑发布流程生成新版本。运行中实例固定绑定提交时的发布版本。
- 删除定义只允许从未被实例引用的草稿；已有实例/审计历史必须可查。
- 同一业务对象同时匹配多个流程时，匹配优先级和冲突处理明确、稳定、可审计；不依赖数据库返回顺序。

## 3. 审批实例与状态机

推荐实例状态：`Draft → Submitted → InProgress → Approved | Rejected | Withdrawn | Cancelled`。待办任务：`Pending → Approved | Rejected | Skipped | Cancelled`。状态改变必须校验当前版本、操作者范围和目标状态；终态不能重复审批。

### 3.1 提交流程

1. 业务模块提交不可变的业务对象引用、租户/主体、业务版本和可查询的安全字段快照。
2. WorkflowForm 依据已发布版本建立实例与首批任务。若业务状态需要同步改为“审批中”，通过业务模块合同参与本地事务或通过明确的异步一致性状态机完成。
3. 通过 Outbox 发布待办/流程事件；事件失败可重试，不重复生成逻辑实例。

### 3.2 审批、会签和条件

- 审批命令带任务 ID、期望版本/状态、意见和幂等键；在一次事务中完成权限校验、任务状态更新、审批审计和后续任务激活。
- 角色、用户、组织策略在任务生成时形成可解释的候选人快照；提交时与审批时的权限变化处理规则明确。已离职/禁用候选人需要可见的重新指派/升级流程。
- 会签模式区分“所有人同意”“任一人同意”等策略；拒绝优先级、重复审批和审批人兼任提交人的处理由流程版本固定。
- 条件表达式只允许访问白名单字段和受限运算符，不执行任意脚本/表达式代码。缺字段、类型不匹配、敏感字段或规则异常应使流程进入可诊断失败状态，不得默认为条件通过。
- 条件步骤/分支只在发布后的规则完整验证后执行；为已发布实例记录命中的分支和评估输入版本。

### 3.3 驳回、撤回与业务回调

- 业务模块对 `Approved/Rejected/Withdrawn/Cancelled` 定义允许的业务状态转换及补偿。
- 回调失败时审批结果仍保留为可重试待同步状态，或采用事务性命令；不可让界面显示“业务已通过”而业务单据仍处于未审批状态且无告警。
- 撤回仅在流程策略允许、当前未完成并由有权限主体发起时成功；撤回不删除审批记录。
- 业务对象已被修改时按业务版本策略拒绝、要求重提或要求审批人查看差异。

## 4. 动态表单

- Schema 按业务类型和版本保存；字段定义含稳定 key、类型、标签资源键、必填/范围/格式校验、显示条件、读写权限、敏感级别和数据保留规则。
- 提交数据必须经过服务端 schema 版本验证；浏览器/PDA 的客户端校验只用于快速反馈。
- 修改 schema 不重解释历史提交；实例记录 schema 版本和必要的只读字段快照。
- 动态表单数据以受限结构存储或经拥有模块正式 DTO 转换；不可将任意字段直接映射为数据库列、权限规则或可执行代码。
- 文件字段只存 Platform 文件引用，不接收可控文件 URL/磁盘路径；访问时再次校验主体、租户和业务对象权限。
- 动态表单与 Builder 源码生成、生成页模板、生成式 CRUD 不耦合。

## 5. 权限、并发和异常

| 情况 | 处理 |
|---|---|
| 非候选人审批或无流程管理权限 | 服务端拒绝；保留必要安全审计 |
| 两个审批人同时完成同一任务 | 乐观并发/原子状态条件更新，只接受规则允许的一次转换 |
| 重复提交/审批命令 | 幂等返回首次确定结果；不重复生成任务或业务回调 |
| 定义草稿有不可达步骤/非法条件/无终点 | 发布失败并逐项返回验证问题 |
| 运行中流程定义更新 | 老实例继续用原版本；新实例按新版本创建 |
| 业务回调或消息暂时失败 | 可观测重试；超过策略阈值进入待人工处理队列，不丢审批记录 |
| 条件字段缺失或类型错误 | 不自动通过；实例暂停为规则异常并提示有权人员 |
| 审批人被禁用或部门变化 | 按发布策略重算/转派/升级；保留原始候选快照 |
| 动态表单文件被越权访问 | Platform 拒绝；流程输出不暴露文件内容 |

## 6. 详细验收用例

| ID | 场景 | 期望 |
|---|---|---|
| WF-TC-001 | 发布合法线性流程、提交业务单据 | 固定版本实例与首个任务生成；业务单据状态与实例状态一致 |
| WF-TC-002 | 起点/终点缺失、不可达节点、空审批人、循环定义 | 发布拒绝并定位问题；无部分发布数据 |
| WF-TC-003 | 同一业务类型多流程匹配与优先级相同 | 结果确定；冲突拒绝或按明示优先级，不依赖查询顺序 |
| WF-TC-004 | 用户/角色/部门审批人候选生成 | 候选人和授权范围正确，形成可审计快照 |
| WF-TC-005 | 非候选人、跨租户用户、无权管理员执行审批 | 拒绝且任务状态不变 |
| WF-TC-006 | 重复审批、审批并发、过期版本提交 | 最多一次合法状态转移；重复请求符合幂等语义 |
| WF-TC-007 | 所有人会签、任一人会签、重复候选人、拒绝 | 会签按照发布策略推进/终止，记录每一参与决定 |
| WF-TC-008 | 条件命中/未命中/字段缺失/类型不匹配 | 分支可重现；异常不会被解释为命中 |
| WF-TC-009 | 提交后发布新流程版本 | 既有实例仍绑定原版；新实例使用新版 |
| WF-TC-010 | 审批完成时业务模块暂时不可用 | 审批事件不丢；待同步状态可重试并产生运维告警 |
| WF-TC-011 | 撤回、驳回、取消的非法状态转换 | 拒绝转换；实例与业务单据均无部分副作用 |
| WF-TC-012 | 表单 schema 缺字段、超范围、伪造字段、版本过期 | 服务端拒绝；不写入未知/未授权字段 |
| WF-TC-013 | 表单文件引用跨租户/跨业务对象 | 下载或提交引用被拒绝并审计 |
| WF-TC-014 | 修改动态表单定义后查询历史实例 | 历史按原 schema 版本呈现，不被当前定义静默改写 |
| WF-TC-015 | Outbox 发布重复、消费者崩溃后重试 | 待办/通知不重复产生业务效果，失败可观测 |

## 7. 需产品确认

业务流程可视化编辑能力、首期是否支持任意图分支/并行网关、会签策略种类、撤回权限、流程超时与升级 SLA、历史表单快照保留期需要逐项确认。未确认前只承诺经过验证的有限流程语义。
