# 全模块页面、功能与详细测试设计规格

- 状态：评审中；统一设计规范已在会话批准，本文供书面范围确认
- 日期：2026-10-23
- 交付阶段：仅文档与文本线框；不实现业务代码，不创建项目骨架或可执行原型
- 依据：[启动设计](../../00-project-startup-design.md)、[范围矩阵](../../01-business-scope-and-status.md)、[架构](../../02-system-architecture.md)、[治理](../../03-engineering-governance.md)、[追踪矩阵](../../04-requirement-design-test-traceability.md)

## 1. 目标与完成边界

将现有模块大纲深化为团队可直接讨论、分工和实现的设计包。每个保留功能均能回答：谁在哪个页面执行什么操作、输入如何校验、谁拥有事实、何时持久化、失败如何处理、通过哪些测试判定正确。

不把界面清单当作完整设计，不把场景名称当作详细测试，不以外部产品功能反推本项目必须实现相同功能。现有未决策略保留明确的决策责任与实现阻断条件，不能用随意选定的默认值掩盖。

本轮交付以下内容：

1. 全局页面/交互/功能/测试规范及覆盖索引。
2. 各模块页面清单、文本线框、字段字典、操作规则和完整非正常状态。
3. 各功能的主流程、拒绝分支、状态机、契约语义、事务、并发、幂等、取消与恢复。
4. 有初始数据、编号步骤、页面及持久化断言、外部副作用次数和清理方式的详细测试。
5. 可核查的 GitHub/互联网参考及逐项采用/不采用说明。
6. 与既有 SCOPE、REQ、TC、ADR 和跨模块验收的追踪关系。

所有新增详细用例状态为 `designed / 未执行`。文档检查不是自动化、Provider、设备、真实浏览器或现场安全测试结果。

## 2. 已批准的统一设计规范

### 2.1 前端与页面骨架

- Web/Simulator 沿用 Vue 3 + Vite + TypeScript + Element Plus；PDA 沿用 UniApp + Vue 3 + TypeScript。
- 依据为 Seven.Master 的三个客户端依赖清单，而非 Skill 中面向其他框架的示例。Nuxt、React、其他桌面组件系统不进入本轮目标架构。
- Web 初始框架预算：顶栏 56px、侧导航 240px，收起 64px；详情侧栏 360–420px。
- 普通桌面表格初始行高 40px；触控操作目标至少 44px。尺寸是设计基线，非全场景强制固定宽度；国际化、字体放大和真实终端验证后可调整。
- 窄窗口将详情切换为抽屉或独立详情页；表格在自身容器滚动，页面不横向溢出。关闭详情恢复选择、过滤及地图上下文。
- 高密度数据用表格/列表，不以每条记录一张卡片表示。普通用户默认使用业务术语，技术字段在可访问的详情中展示。
- 业务单号、设备标识、位置、安全状态和必要错误原因不得因简化界面而隐藏。
- 地图优先的执行/运维入口属于 Orchestration/WCS；环境搭建、仿真、真机切换及只读 SCADA 不转移到该入口的业务 owner。

### 2.2 页面规格字段

每页分配稳定 `PAGE-{DOMAIN}-{NNN}`，至少定义：

| 内容 | 要求 |
|---|---|
| 用户与入口 | 角色、资源权限、租户/仓库/Pack 范围、菜单、深链、返回路径 |
| 布局 | 文本线框、区域预算、滚动归属、窄窗口行为和键盘焦点路径 |
| 数据 | 字段名、语义/类型、单位/精度、必填/只读、来源 owner、空值/未知含义、校验 |
| 列表 | 默认列、搜索与结构化过滤、稳定排序、分页、选择范围、详情关联 |
| 操作 | 业务前提、授权、提交与处理中反馈、最终证据、失败保留输入及安全重试 |
| 页面状态 | 初次加载、后台刷新、首次为空、筛选为空、正常无待处理、错误、部分失败、拒绝、只读、Stale、Offline |
| 可访问性 | 语义标签、键盘/扫码、焦点、错误摘要、颜色以外的状态表达、长文本与翻译扩展 |

没有对应行为的页面状态必须标明不适用及原因，不能省略后默认为支持。

### 2.3 功能规格字段

每个独立用例分配稳定 `FUNC-{DOMAIN}-{NNN}`，关联现有 SCOPE/REQ、页面与 TC：

1. 业务目标、唯一 owner、参与者和前置条件。
2. 主流程、替代流程、明确拒绝分支和状态转换。
3. 请求/响应/事件的必需语义字段、验证点、可查询操作标识与错误语义。
4. 事务提交点、Outbox/Inbox、并发版本、幂等键的作用域与重复结果。
5. 外部调用超时、结果未知、取消、补偿、重启/断连后的恢复。
6. 权限/租户/数据范围、审计、可观测信息及用户可见解释。

契约描述是设计语义，不伪造已经存在的 API 地址、错误码实现或设备能力。建议的新行为须单独标为 `proposed`，经批准后才能成为实现要求。

### 2.4 详细测试规格字段

新增详细测试使用 `DTC-{DOMAIN}-{NNN}`，保留原 TC 不改号、不覆盖：

- 关联 PAGE、FUNC、REQ、原 TC 与测试优先级/层级。
- 明确角色、数据范围、系统状态、固定测试数据与故障注入点。
- 编号操作步骤，每步明确触发行为，不使用“操作正常”之类泛化描述。
- 页面可见结果、服务端最终/中间状态、账本/预约/任务的增减及副作用次数。
- 拒绝、并发失败、重复投递时必须保持不变的事实。
- 可重复运行的隔离/清理方式及证据采集。
- 适用的 SQL Server/PostgreSQL/MySQL、Adapter、UniApp 端和现场条件。

共用 UI 场景可以用适用矩阵引用，但每页需声明适用性与必要变体。不能用共用测试代替收货记账、预约竞争、命令回读等领域断言。

## 3. 模块分解与覆盖范围

按既有 owner 分包；以下是文档交付顺序，不是实施优先级或新增产品模块。

| 设计包 | 页面/功能覆盖重点 | 权威依据 |
|---|---|---|
| Platform 与安全 | 登录/失效/会话、用户角色部门菜单、数据范围/租户、字典配置国际化文件、审计和安全日志 | [Platform](../../modules/platform-and-security.md) |
| Workflow/Form | 定义与版本、审批工作台/详情、条件/会签、撤回驳回、运行时表单定义和实例 | [Workflow/Form](../../modules/workflow-and-forms.md) |
| Notifications/Jobs | 告警确认/清除、渠道投递、消息/死信、任务计划与执行记录、公告、缓存/HotStore 只读诊断 | [通知与任务](../../modules/notifications-and-jobs.md) |
| WMS | 仓库/货位/容器主数据、库存/流水/预留、入库收货组盘上架、出库拣选发运、盘点、移库、TransferOrder 扩展 | [WMS](../../modules/wms-and-ledger.md) |
| PDA | 登录、在线任务/扫码、收货上架拣选盘点发运、异常报告、只读缓存/过期/恢复联网 | [PDA](../../modules/pda.md) |
| Orchestration/运维 | 2D 主工作台、订单/Leg/交接、命令申请与结果、问题指派/升级/验证/复开 | [Orchestration](../../modules/orchestration.md) |
| Stacker | 包级监控/任务/双深分配/资源、设备状态与联锁、地图上下文动作与恢复 | [Stacker](../../modules/wcs-stacker.md) |
| FourWay | 车辆/层内交通、停车预约和出库、跨层提升机、任务/预约与异常恢复 | [FourWay](../../modules/wcs-fourway.md) |
| External WCS | 连接/能力、外部运输映射、下发/查询/取消/回调诊断，明确供应商能力缺失 | [外部 WCS](../../modules/external-wcs-and-device-adapters.md) |
| DeviceIntegration | 语义设备/连接与健康、命令/反馈关联、协议诊断和脱敏，不作为普通用户裸报文控制台 | [DeviceComm](../../modules/device-communication.md) |
| Simulator/SCADA | 环境地图编辑/校验、部署 manifest、仿真/注入/结果、真机 Promote、只读 SCADA 投影 | [环境/仿真/SCADA](../../modules/environment-simulation-and-scada.md) |

| 系统运维/部署 | 健康、日志/指标关联、部署配置证据、隔离恢复与单写者检查；无现成 UI 的能力设计为受控操作手册，不强造网页部署按钮 | [架构](../../02-system-architecture.md)、[跨模块验收](../../acceptance/01-cross-module-and-provider-matrix.md) |

## 4. 文档结构与追踪

在 `docs/detailed-design` 建立：

- `README.md`：覆盖索引、阅读/评审顺序、模块设计包入口。
- `00-shared-page-and-test-standard.md`：可复用页面、功能、用例规范与共用 UI 测试。
- `01-reference-cases.md`：公共来源、读取日期、证据范围、借鉴/不采用及失效来源。
- 每个设计包一个 Markdown 文档，分页面、功能和详细测试三部分；过大时可按业务子流程拆分，索引必须完整。

现有 `docs/modules`、Route 和 ADR 保持业务权威；新增包深化交互和可验证步骤，不复制出第二套冲突状态机。同步 README、模块入口和总追踪矩阵，使页面/功能/测试可以双向查找。

旧范围 REQ 只有范围映射、没有逐条规范定义的，先依据既有权威章节核实语义，再补齐定义及覆盖；证据不足则标明未决项与实现阻断条件，不宣称追踪已经闭合。

## 5. Skill 使用与冲突处理

- `brainstorming`：先确定统一规范和书面交付范围。
- `product-ui-taste`：高密度页面阅读、框架预算、列表/详情、真实数据边界和完整状态。
- `frontloom-core-fe` / `frontloom-vue`：语义、可访问性、Vue 状态边界、类型契约与测试设计；不导入不适用的 Nuxt 实现。
- 后续按功能使用适用的测试/认证/错误处理/数据库/可观测性 Skill，避免与任务无关地加载。

规则优先级：已批准项目不变量与安全边界优先于通用 Skill 的美学或便利建议。

特别说明：

1. 不自动切换模式、解除联锁、提升权限或满足控制前提。
2. 不离线排队/保存/重放写操作，不以 optimistic UI 证明库存或物理成功。
3. 缺失必需前提的控制可明确禁用并给出可键盘访问的原因，服务端仍须拒绝；不因“按钮必须可用”绕过约束。
4. 无真实总工作量时不伪造进度百分比；用阶段、耗时、最近确认和可查询操作记录反馈。
5. 地图需列表替代路径；不能以画布图形可见代替可访问、可发现和状态完整。

## 6. 外部案例研究方法

每个案例记录公开 URL、读取日期、证据类型（官方文档/源码/演示截图/二手文章）、适用模块、具体借鉴点与明确不采用项。

已初步核验：

| 来源 | 借鉴方向 | 不直接采用 |
|---|---|---|
| [ERPNext Pick List](https://docs.frappe.io/erpnext/pick-list) | 单据关联、待拣数据、位置明细、扫码和库存变化后的再校验 | 不未经批准引入其 FIFO/临期分配策略或制造业务 |
| [ERPNext Stock Ledger](https://docs.frappe.io/erpnext/stock-ledger) | 流水到来源单据的追溯 | 不扩展成本/估值/财务范围，不改变 WMS 权威 |
| [OpenWMS](https://github.com/openwms/org.openwms) | WMS/MFC 分工、外部系统和设备适配边界 | 不引入其 Java 栈、微服务部署或独立存储架构 |
| [Element Plus Table](https://element-plus.org/en-US/component/table.html) | 表格固定头/列、选择、表格滚动 | 不把悬浮 tooltip 当作唯一完整信息路径 |
| [Element Plus Form](https://element-plus.org/en-US/component/form.html) | 标签、字段规则、提交校验 | 不以客户端校验代替服务端权限/业务校验 |

研究中通用 Web 搜索出现网关超时、openTCS 文档链接出现连接失败；这些不作为已核验内容。后续可通过公开源码/官方替代入口核验，不用未读取的资料支撑具体结论。

外部资料只做概括与引用，不复制大段实现、界面资产或不明确许可的内容。不会向外部搜索或服务上传本项目私有文档/代码。

## 7. 验证与评审门禁

1. 范围完整性：每个保留 SCOPE 有设计包；预留/未决/移除明确区分。
2. 追踪完整性：PAGE/FUNC/DTC 标识唯一；页面关联功能、功能关联需求与用例；不存在无解释的孤项。
3. 测试可执行性：抽查并逐项确认数据、步骤、持久化/副作用断言和清理，不接受仅有场景名称的条目。
4. 业务一致性：库存权威、Pack 控制、持久预约/fencing、地图版本部署、问题/告警分离、离线只读不变。
5. UI 一致性：布局、页面状态、危险操作、长文本/翻译、键盘与扫码、窄窗口有明确预期。
6. 链接与文本：UTF-8 检查、相对链接存在、VS Code Problems；外部暂不可访问项显式记录。
7. 运行证据：本轮不执行/宣称业务测试、真实设备测试或屏幕验证通过。
